# The Oregon Trail 5th Edition — Windows 10/11 fix and 2× scaler

A drop-in `winmm.dll` that makes the GOG release of **The Oregon Trail 5th Edition** (2001)
run cleanly on modern Windows, in a 1280×960 window instead of a 640×480 one.

No game files are modified. Delete the two files below and the game is exactly as it was.

## Install

1. Download `winmm.dll` and `OT5.exe.manifest` from the latest release.
2. Copy both into the game folder, next to `OT5.EXE`.
3. Run `OT5.EXE` (or launch from GOG Galaxy as usual).

To uninstall, delete those two files.

## What it fixes

| Stock game on Windows 10/11 | With this fix |
|---|---|
| Switches the whole desktop to 640×480 on start (and again whenever it regains focus) | Desktop resolution is left alone; the game runs in a normal window |
| 640×480 window — tiny on a modern display | Main window, movies, trail map and the main pop-ups are drawn at 2×, pixel-exact |
| No title bar — can't move it | Title bar with move and minimise |
| Pauses, minimises itself, blacks out movies or restarts the music over a movie when you click away | Keeps running in the background; never told it lost focus |
| Saving or loading from anywhere but the game folder breaks movie playback and can freeze the game | Fixed (the game looked up its data folder relative to the current directory) |

Scaled 2×: main window, all Bink movies, trail map, Conversation, Diary, Guidebook, Health,
Purchase Inventory. Left at native size (they read fine): character creation, prologue,
wagon-train picker, resting, and system dialogs such as the quit confirmation.

## Requirements

- The **GOG** version of The Oregon Trail 5th Edition. Built and tested against `OT5.EXE`
  MD5 `a652e8afd07e798b62bbbbe6d7f17309`. Other releases are untested.
- Windows 10 or 11. Tested on Windows 11 at 100% display scaling. At higher scaling Windows
  will stretch the window further (it is DPI-unaware by design), which may look soft.

GOG ships its own `ddraw.dll` in the game folder. Leave it; with this fix nothing loads it.

## Files

- `winmm.dll` — the fix. It is a proxy: every real multimedia call is passed on to Windows'
  own `winmm.dll` from the system folder, so no Microsoft file is bundled.
- `OT5.exe.manifest` — marks the game DPI-unaware so Windows does not rescale the 2× output.

## Troubleshooting

Create an empty file named `scaler.log` in the game folder and start the game; the fix then
writes a diagnostic log there (window creation, hooked calls, a heartbeat every 10 s).
Delete the file to turn logging off again. Nothing is written to the game folder otherwise.

If the game still switches your desktop to 640×480, the fix isn't being loaded. Check with the
log: it should contain `real winmm: 0 of 192 exports unresolved`. If `scaler.log` stays empty,
Windows loaded its own `winmm.dll` instead. The usual cause is a compatibility setting or
shim on `OT5.EXE`; clear the Compatibility tab in the EXE's Properties.

## How it works

The game draws everything with plain GDI, so the DLL patches the game's import table at load
and doubles coordinates on the way out (blits, text, regions, lines, clipping) and halves
mouse coordinates on the way in. Bink is denied its runtime DirectDraw load, which makes it
fall back to a GDI `StretchBlt` path that can be scaled the same way. `ChangeDisplaySettingsA`
is answered with success without touching the display. Focus loss is hidden by subclassing
every top-level window the game creates and dropping deactivation messages.

## Building

Requires only PowerShell; `build.ps1` downloads the pinned Zig 0.16.0 toolchain into `tools\`
on first run and produces `winmm.dll`:

```powershell
.\build.ps1
```

`src\stubs.S`, `src\winmm.def` and `src\winmm_names.h` are generated by
`src\gen_stubs.py` (Python + `pefile`) from the system's 32-bit `winmm.dll`; they are
committed, so you only need to rerun the generator if Windows adds winmm exports.
